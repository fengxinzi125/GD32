# 实验七：SD 卡访问学习路径与双版本源码导读

本文依据当前目录的两份实际项目源码整理：`07.SDCardAccess`（下称 **SDIO 版**）与 `07.SDCardAccess（SPISWMODE）`（下称 **软件 SPI 版**）。讲解顺序是“作用 → 代码 → 拆解 → 例子 → 注意事项”，重点衔接你已经学习的指针、SRAM 与裸机任务轮询。

本次只新增本文，没有修改实验代码，也没有重新编译、下载或验证开发板。文中的预期结果是实验观察目标；源码中确定的行为与需要硬件验证的现象会分别说明。下文文件路径均相对于各自项目根目录；特别标注“SDIO 版”或“SPI 版”时，请打开对应版本。

## 一、先选版本：建议怎样学、怎样用

**按你当前的基础，建议先用软件 SPI 版读懂通信与块访问，再学习 SDIO 版作为后续主线。** 软件 SPI 版能直接看到每一位如何发送、每个字节如何接收，容易把指针与缓冲区联系起来；SDIO 版适合进一步掌握外设、DMA、中断与错误处理。这个建议针对学习顺序，并不表示软件 SPI 版更可靠。

如果目标是后续实现文件存储、图片读取等较多数据的访问，优先把 **SDIO 版作为工程发展基础**，但应先处理第九节的问题。两份代码都属于教学示例，不能把“界面能读写”直接等同于接口已具备完善的边界和故障处理能力。

### 1. 两份代码到底有什么区别

| 对比项 | SDIO 版 | 软件 SPI 版 |
| --- | --- | --- |
| 驱动入口 | `App/SDCard/SDCard.c`、`SDCard.h` | `App/SDCard/SDCardBySPI.C`、`SDCardBySPI.h` |
| 数据传输 | SDIO 外设，初始化后切换 4 位总线，选择 DMA | GPIO 软件翻转时钟，逐位收发 |
| 底层读接口 | `sd_block_read(buf, byteAddr, blocksize)` | `SDReadSector(buf, sector, sectorNum)` |
| 第二参数单位 | **字节地址**；高容量卡由驱动内部除以 512 | **扇区号**；非高容量卡由驱动内部乘以 512 |
| 写接口 | `sd_block_write()` | `SDWriteSector()` |
| 搬运数据者 | DMA 在 SRAM 与 SDIO FIFO 之间搬运 | CPU 调用 `ReadWriteByte()` 搬运 |
| 完成通知 | SDIO 中断更新完成、错误状态；函数仍存在等待 | 同步循环等待数据、令牌和响应 |
| 块大小 | 业务取 `card_blocksize`；高容量卡为 512 | 宏 `SD_SECTOR_SIZE` 固定 512 |
| 容量来源 | `sd_card_information_get()` 解析结构体 | `SDGetSectorCount()` 解析 CSD，返回扇区数 |
| 插卡检测 | PD3，输入浮空；业务缓存检测状态 | PD3，上拉输入；业务读写前直接检测 |
| 调速实现 | 初始化与传输使用不同 SDIO 分频值 | `SetSpeedLow()`、`SetSpeedHigh()` 均为空 |
| 应用层 | GUI、按字节读写、2048 字节缓冲区 | 基本相同；底层调用与卡状态处理不同 |
| 当前主要学习价值 | SDIO 命令、DMA、中断、状态协调 | GPIO 时序、移位运算、命令封装、指针遍历 |

逐文件内容核对后，公共源码中差异集中在 `App/Main/Main.c`、`App/ReadWriteSDCard/ReadWriteSDCard.c` 和工程配置，核心驱动文件被替换；GUI、定时器等公共模块内容相同。`Main.c` 的初始化与主循环主线相同。不要仅因 SPI 版工程还列入了 `gd32f30x_dma.c`、`gd32f30x_sdio.c`，就认为它实际通过 DMA 或 SDIO 读卡：应沿调用链判断。

### 2. 引脚如何复用

| MCU 引脚 | SDIO 版作用 | 软件 SPI 版作用 |
| --- | --- | --- |
| PC12 | CK | CLK，由软件拉低、拉高 |
| PD2 | CMD | MOSI，MCU 发给卡 |
| PC8 | D0 | MISO，卡发给 MCU |
| PC9 | D1 | 本 SPI 驱动未配置使用 |
| PC10 | D2 | 本 SPI 驱动未配置使用 |
| PC11 | D3 | CS，低电平选中 |
| PD3 | CD，低电平检测到插卡 | CD，低电平检测到插卡 |

以上是 `gpio_config()` 与 `InitBSP()` 能确认的**代码配置**。是否与手上开发板卡座连线、上拉电阻和检测开关一致，必须对照原理图或测量。切换版本是重新下载相应工程，不能让两套驱动同时控制同一组引脚。

### 3. 为什么软件 SPI 版可能明显更慢

`ReadWriteByte()` 每一位包含两次 `DelayNus(10)`。仅显式延时，一位至少约 20μs，一字节约 160μs，一个 512 字节数据区约 81.92ms；此外还有 GPIO 函数开销、命令、令牌、响应、卡忙等待和中断影响。

因此约 50kHz 只是按延时计算的时钟上限估计，不是实测速度。两个调速函数为空，不能依据“进入高速模式”注释认定已经提速。SDIO 版具备更高吞吐量的实现基础，实际差距应通过相同卡、相同数据量的测量确认。

## 二、本实验是什么、为什么需要、怎么使用

### 1. 实验目标

这两个 GD32F303ZE 裸机工程通过触摸屏输入十六进制地址、数据和长度，读取 SD 卡原始数据，或修改指定地址的一个字节，并把信息显示到屏幕终端和 115200 波特率串口。

这里没有文件名、目录、`f_open()` 或文件系统挂载流程。操作的是 **SD 卡原始字节地址**。地址 515 表示卡存储空间中的偏移，不是 MCU 地址 `0x20000000`，也不能把 515 强转成指针后解引用来访问 SD 卡。

写入会改变卡的原始内容，地址 0 等位置可能包含分区或文件系统信息。动手写入请使用可丢弃数据的专用实验卡，先备份并确定测试区域。本文的 515 等数字首先用于纸面推演，不代表那里一定可安全写入。

### 2. 从上一实验迁移过来的知识

| 已学内容 | 本实验中的连接点 |
| --- | --- |
| SRAM | `s_arrSDBuffer[2048]` 是 MCU 侧临时缓冲区 |
| 掉电丢失 | SRAM 缓冲区掉电丢失；卡上已完成写入的数据用于持久保存 |
| 内存池 | 本实验主线没有 `MyMalloc()`；主要使用静态数组 |
| 指针 | 把缓冲区地址传给驱动，让驱动填入收到的字节 |
| 块管理 | 这里的块是卡传输单位，不是上一实验的 32 字节分配块 |
| 定时标志 | 主循环轮询任务；读写与延时仍可能阻塞其他任务 |

“在 RAM 中改了缓冲区”和“把缓冲区写回 SD 卡”是两件事。理解这个区别，才能理解为什么单字节写入也要执行一次整块读取和整块写回。

### 3. 必须先弄清的概念

| 概念 | 是什么 | 为什么需要、在项目中怎么用 |
| --- | --- | --- |
| 块／扇区 | 数据传输的成组单位 | 本文主要以 512 字节推演；业务把零散访问转换成整块访问 |
| SDIO | MCU 用来与卡交换命令、数据的外设 | SDIO 版用 CMD、CK 与 D0～D3 完成传输 |
| 软件 SPI | 用 GPIO 模拟串行收发 | CPU 控制 CLK、MOSI、CS，并采样 MISO |
| FIFO | 外设内部的数据队列 | SDIO 与内存之间通过 FIFO 交接数据 |
| DMA | 硬件按照配置在内存和外设间搬运数据 | 这里使用 DMA1 的通道 3，减少 CPU 逐字搬运 |
| CID | 卡身份相关信息 | 可读取制造商、产品等字段 |
| CSD | 卡能力与容量相关信息 | 两版都通过它计算容量，但实现都有容量边界问题 |
| RCA | SDIO 流程中的卡相对地址 | SDIO 版识别卡后用于选卡等命令；不是存储偏移 |
| CD | 卡座插入检测信号 | 只说明检测引脚状态，不能证明通信已初始化成功 |
| CRC | 传输校验 | SDIO 驱动处理 CRC 错误；SPI 示例读数据后读走两字节 CRC，但未验证其内容 |

## 四、初始化、主循环与关键调用链

### 1. 共同的程序骨架

```text
启动文件 → SystemInit → C 运行库初始化 → main
main
 ├─ InitHardware
 │   ├─ InitRCU
 │   ├─ InitNVIC
 │   ├─ InitUART0(115200)
 │   ├─ InitTimer
 │   ├─ InitSysTick
 │   └─ InitEXMC
 ├─ InitSoftware
 │   ├─ InitLED → InitLCD → InitJPEG → InitBMP → InitTouch
 │   └─ InitReadWriteSDCard
 └─ while (1)
     ├─ Proc1msTask → 每累计20次标志调用 ScanTouch
     ├─ Proc2msTask → LEDFlicker(250)
     │               每累计20次标志调用 ReadWriteSDCardTask
     └─ Proc1SecTask → 检查并清标志，当前无实际业务
```

名义触摸扫描间隔约 20ms，SD 卡业务与 GUI 约 40ms；业务每累计 25 次再检测插卡，名义约 1s。`GUITask()` 的注释写每隔 20ms，但此工程实际从约 40ms 的业务任务调用，应以调用条件为准。

这些周期建立在主循环及时处理标志的前提上。布尔标志只能表示“发生过”，阻塞期间多次中断置位不会自动累计成同样次数的待办任务；长读写、串口输出和 `DelayNms(1000)` 都会影响实际响应。

### 2. SDIO 版初始化

```text
InitReadWriteSDCard
 ├─ 本文件 static InitSDCard
 │   ├─ 循环 sd_init，失败则显示提示并延时闪灯
 │   │   ├─ rcu_config、gpio_config、sdio_deinit
 │   │   ├─ sd_power_on：CMD0、CMD8、CMD55 + ACMD41
 │   │   └─ sd_card_init：CMD2取CID、CMD3取RCA、CMD9取CSD
 │   ├─ sd_card_information_get(&s_structSDCardInfo)
 │   ├─ PrintSDInfo
 │   ├─ sd_card_select_deselect：CMD7选卡
 │   ├─ sd_cardstatus_get：CMD13，检查锁卡位
 │   ├─ sd_bus_mode_config(SDIO_BUSMODE_4BIT)
 │   ├─ sd_transfer_mode_config(SD_DMA_MODE)
 │   └─ nvic_irq_enable(SDIO_IRQn, 0, 0)
 ├─ 设置 beginAddr、endAddr、读写回调
 ├─ InitGUI(&s_structGUIDev)
 └─ 显示地址范围
```

`sd_init()` 成功不等于整个业务初始化全部成功：选卡、总线切换和后续步骤仍有各自返回状态。驱动末尾还有 `sd_io_init()` 辅助封装，但当前业务主线没有调用它；不要误认为它和业务的 `InitSDCard()` 是同一个函数。

### 3. 软件 SPI 版初始化

```text
InitReadWriteSDCard
 ├─ 循环调用驱动公开的 InitSDCard()
 │   ├─ InitBSP：配置GPIO
 │   ├─ SetSpeedLow（空函数）
 │   ├─ 发10个0xFF，产生80个时钟
 │   ├─ CMD0进入空闲
 │   ├─ CMD8检测接口条件
 │   ├─ V2路径：CMD55 + CMD41，CMD58读OCR判断高容量
 │   ├─ 旧卡路径：CMD55 + CMD41，或CMD1；设置512字节块长
 │   └─ DisSelect、SetSpeedHigh（空函数）
 ├─ SDGetSectorCount() * 512 计算字节范围
 ├─ 注册读写回调 → InitGUI
 └─ 显示地址范围
```

两版都有 `InitSDCard` 这个名字，但 SDIO 版是业务文件内的 `static void` 函数，SPI 版是驱动公开的 `u32` 函数，作用范围、返回值不同。

### 4. 一次按键读取的完整路线

```text
ScanTouch 更新触摸状态
 → GUITask → ScanGUIButton
 → GetGUILineEditRusult(..., &readAddr / &readLen)
 → s_pGUIDev->readCallback(readAddr, readLen)
 → ReadSDCard → 检查卡与地址 → Read
 → SDIO：sd_block_read
   或 SPI：SDReadSector → SendCmd → RecvData → ReadWriteByte
 → buff[i] 取得数据 → showLine 与 printf 输出
```

写入路线类似：`writeCallback → WriteSDCard → Write → 整块读取 → 改一个字节 → 整块写回`。

## 六、把指针、块对齐与单字节访问真正读懂

### 1. 先区分四种“地址”

```c
u8 *buff = s_arrSDBuffer;
u32 addr = 515;
```

`buff` 保存 MCU 内存中的地址；`*buff` 是此地址处的一个字节；`&buff` 是指针变量本身的地址。`addr` 保存卡中的字节偏移，驱动通过命令告诉卡要访问哪里。

| 表达式 | 含义 |
| --- | --- |
| `s_arrSDBuffer` | 多数表达式中转换成第一个数组元素的地址 |
| `s_arrSDBuffer + 3` | 缓冲区第3个偏移位置的地址 |
| `buff[i]` | 等价于 `*(buff + i)`，读取对应字节 |
| `buff += 512` | 指针向后移动512个 `u8` 元素，即512字节 |
| `u32 *p; p++` | 向后移动一个 `u32` 元素，在本平台为4字节 |

指针参数也是值传递：函数收到地址值的副本，修改副本不会自动修改调用者的指针变量；通过副本指向的地址写数据，则会改变调用者提供的数组。

### 2. `Read(u32 addr, u32 len)`：按字节需求，整块读取

**作用：** 返回指向所需数据起点的指针。`addr`、`len` 单位都是字节；返回值是共享静态缓冲区中的地址，原实现没有用返回值报告读失败。

SDIO 版的关键原代码摘录如下，SPI 版只是在整块读取处改用 `SDReadSector(buff, addr / 512, 1)`：

```c
addrOffset = 0;
while (0 != (addr % s_structSDCardInfo.card_blocksize)) {
    addr = addr - 1;
    addrOffset = addrOffset + 1;
}
buff = s_arrSDBuffer;
len = len + addrOffset;
/* 循环内扣减len，每次读取一整块，然后前移卡地址与缓冲区指针 */
sd_block_read(buff, addr, s_structSDCardInfo.card_blocksize);
/* ... */
result = s_arrSDBuffer + addrOffset;
return result;
```

执行步骤：

1. 将卡地址逐字节向前退到块首，同时记录退了多少字节。
2. 将需求长度加上块内偏移，覆盖从块首到需求末尾的所有数据。
3. 每轮读入一整块，即使剩余需求不足一块。
4. 卡地址增加一块，缓冲区指针也前移一块。
5. 返回“缓冲区起点 + 最初块内偏移”，让调用者直接按原需求读取。

假定块长512，调用 `Read(510, 4)`：

```text
需求：卡地址510、511、512、513，共4字节
对齐：块首0，偏移510；覆盖长度=510+4=514
第1次：卡[0..511]   → 缓冲区[0..511]
第2次：卡[512..1023]→ 缓冲区[512..1023]
返回：s_arrSDBuffer + 510
返回指针p：p[0]→卡510，p[1]→卡511，p[2]→卡512，p[3]→卡513
```

这里读了1024字节，向上层提供其中4字节。返回地址仍位于同一个2048字节静态数组中，没有动态申请内存，因此不能对它调用 `MyFree()` 或 `free()`。下次读写复用缓冲区会覆盖旧内容，需要长期保存时应复制到另一块足够大的空间。

**注意：** 返回局部指针变量的“值”并不等于返回局部变量自身的地址。`result` 虽然是局部变量，但它保存的地址指向静态数组，函数返回后数组仍存在。

### 3. `Write(u32 addr, u8 data)`：先读、再改、后写

**作用：** 修改卡中的一个字节。`addr` 是字节地址，`data` 是一个8位数据；返回 `void`，当前实现不向上层报告成功或失败。

SDIO 版关键原代码：

```c
sd_block_read(s_arrSDBuffer, addr, s_structSDCardInfo.card_blocksize);
s_arrSDBuffer[addrOffset] = data;
sd_block_write(s_arrSDBuffer, addr, s_structSDCardInfo.card_blocksize);
```

这三句执行前，`addr` 已对齐到块首。SPI 版相应地调用 `SDReadSector()` 和 `SDWriteSector()`，传入的是 `addr / SD_SECTOR_SIZE`。

例如 `Write(515, 0xA5)`，块长512：

1. 找到块首512，块内偏移3。
2. 把卡地址512～1023读入缓冲区。
3. 只改 `s_arrSDBuffer[3]`。
4. 把整个512字节块写回。

先读取是为了保留其他511字节。若读取失败却继续写回，缓冲区可能保留上一次操作的数据，导致同块其他位置被错误改写；当前两版都没有在这里检查返回值。

### 4. `ReadSDCard()`、`WriteSDCard()`：业务入口

`ReadSDCard(u32 addr, u32 len)` 接收字节地址与字节数，返回 `void`。它检查插卡和地址，显示请求信息，调用 `Read()`，然后通过 `buff[i]` 逐字节显示。

`WriteSDCard(u32 addr, u8 data)` 接收字节地址与一个字节，返回 `void`。它检查插卡和单地址范围，打印请求后调用 `Write()`。屏幕出现 `Write: ...` 只是打印了请求，不证明实际写入成功；确认应靠错误码和读回比较。

GUI 地址输入最多8位十六进制，数据和读取长度各最多2位。输入 `10` 表示16，输入 `FF` 表示255，`00` 表示0；不是十进制10、也不是字符串文件名。两位数据经解析后在0～255，传给 `u8 data` 可以容纳；若以后开放更宽输入，应显式拒绝超过 `0xFF` 的数据。

### 5. `GetGUILineEditRusult()`：返回值与输出参数分工

```c
u32 readAddr;
if (0 == GetGUILineEditRusult(GUI_LINE_EDIT_READ_ADDR, &readAddr)) {
    /* readAddr 已经被填写，可交给业务回调 */
}
```

参数一选择输入框，参数二是 `u32*`，用于把解析结果写回；返回 `u8`，0表示获取成功，其他值表示失败。实现用 `sum = sum * 16 + charValue` 累积，最后 `*result = sum`。

输入 `20F`：先得到2，再得到 `2*16+0=32`，最后得到 `32*16+15=527`。函数没有接收 `readAddr` 的初始值，而是接收它的地址，才能修改这个变量。调用者必须传有效可写的 `u32` 地址；当前函数没有检查空指针，遇到非十六进制字符会结束解析，不是完整的通用输入校验器。

### 6. 回调与结构体指针

```c
/* 业务层 */
s_structGUIDev.readCallback = ReadSDCard;
InitGUI(&s_structGUIDev);

/* InitGUI中 */
dev->showLine = ShowStringLineInGUITerminal;
s_pGUIDev = dev;

/* GUITask中 */
s_pGUIDev->readCallback(readAddr, readLen);
```

给函数指针赋值是保存“以后调用谁”，最后一句才会执行该函数。`dev->showLine` 相当于 `(*dev).showLine`。`InitGUI()` 收到结构体地址的副本，却能修改原结构体成员，因为两者指向同一个对象。

`s_structGUIDev` 使用静态存储期，是因为 GUI 保存了它的地址，并在初始化函数返回后继续使用。若把它改为初始化函数里的普通局部结构体，再保存其地址，后续就可能访问已失效的对象。

## 七、软件 SPI 核心函数逐层学习

### 1. `ReadWriteByte(u8 data)`：发送一字节，同时接收一字节

**参数：** 要发送的8位数据。**返回：** 从MISO采样得到的8位数据，不是成功标志。

```c
for (i = 0; i < 8; i++) {
    gpio_bit_reset(GPIOC, GPIO_PIN_12);
    /* 根据 data & 0x80 设置 MOSI */
    DelayNus(10);
    gpio_bit_set(GPIOC, GPIO_PIN_12);
    DelayNus(10);
    readData = (readData << 1) | gpio_input_bit_get(GPIOC, GPIO_PIN_8);
    data = data << 1;
}
```

先取最高位设置MOSI，再抬高时钟并采样MISO，左移后处理下一位。发送 `0xA5` 时，MOSI依次为 `1 0 1 0 0 1 0 1`；返回字节由卡的MISO决定，通常不等于发送值。接收时发送 `0xFF` 是为了继续提供时钟，让卡能输出数据。

### 2. `SendCmd(u8 cmd, u32 arg, u8 crc)`：封装命令

**参数：** 命令编号、32位命令参数、发送的CRC字节。**返回：** 读到的卡响应字节，用 `u32` 类型返回；选卡失败返回 `0xFF`。不要把所有非零响应都理解成同一种错误，例如初始化的空闲响应是 `0x01`。

步骤：取消上次片选 → 选卡并等就绪 → 发送 `cmd | 0x40` → 参数从高字节到低字节发送 → 发送CRC → 必要时处理CMD12额外字节 → 循环读取响应。

例如 `SendCmd(CMD0, 0, 0x95)` 发出的6字节为 `40 00 00 00 00 95`。SPI初始化通过它请求空闲状态，后面再检查响应。

### 3. `RecvData(u8 *buf, u32 len)`：指针填充缓冲区

参数是目标缓冲区首地址和字节数；返回0成功、非0失败。先等起始令牌 `0xFE`，再循环：

```c
*buf = ReadWriteByte(0xFF);
buf++;
```

最后读走两个CRC字节，但未验证。若调用 `RecvData(array, 512)`，调用者必须提供至少512字节空间。函数里的 `buf++` 只移动本地指针副本，`*buf = ...` 则真实改变数组内容。

### 4. `SendBlock(u8 *buf, u8 cmd)`：发送数据包

参数 `buf` 指向512字节数据，`cmd` 在这里实际用作数据令牌：单块 `0xFE`、多块数据 `0xFC`、多块停止 `0xFD`。返回0表示通过本函数检查，1表示等待失败，2表示数据响应不接受。

步骤：`WaitReady()` → 发令牌 → 非停止令牌时发512字节、两字节占位CRC → 检查响应低5位是否等于 `0x05`。它在收到数据接受响应后没有再等待本次编程忙结束，不能把返回0直接解释为已经持久写完。

### 5. `SDReadSector()` 与 `SDWriteSector()`：必须记住参数单位

```c
u32 SDReadSector(u8 *buf, u32 sector, u32 sectorNum);
u32 SDWriteSector(u8 *buf, u32 sector, u32 sectorNum);
```

参数依次为缓冲区、起始扇区号、扇区数量；返回0成功、非0失败。缓冲区应能容纳 `512 * sectorNum` 字节，数量必须大于0。高容量卡直接用扇区号；非高容量卡在驱动内部执行 `sector <<= 9` 转为字节地址。

单扇区读取用CMD17，再 `RecvData(buf, 512)`；多扇区用CMD18、连续收包、CMD12停止。单扇区写入用CMD24和 `SendBlock(buf, 0xFE)`；多扇区用CMD25、`0xFC`数据令牌、`0xFD`停止令牌。

例如卡的字节地址512对应扇区1，调用形式是 `SDReadSector(buf, 1, 1)`，不是把512直接当第二参数。当前应用层虽然有多扇区接口可用，但 `Read()` 仍逐次调用单扇区读取。

### 6. 辅助接口

| 函数 | 参数与返回值 | 使用例子与注意 |
| --- | --- | --- |
| `InitSDCard()` | 无参数；0成功，非0失败 | 调用成功后才能进行卡访问；内部初始化GPIO并识别类型 |
| `SDDetect()` | 无参数；0检测到插卡，1未插入 | `if (0 == SDDetect())` 只检查卡座状态 |
| `SDGetCID(cid)` | 至少16字节输出区；0成功 | `u8 cid[16]; SDGetCID(cid);`，必须检查返回值 |
| `SDGetCSD(csd)` | 至少16字节输出区；0成功 | 先取原始CSD，再解析容量字段 |
| `SDGetSectorCount()` | 无参数；返回512字节扇区数，0表示失败 | 不能直接当作字节容量；当前高容量分支解析不完整，见第九节 |
| `WaitReady()` | 无参数；0收到 `0xFF`，1超时 | 重复发送 `0xFF` 并读取；计数超时并非固定毫秒 |

## 八、SDIO 与 DMA 核心函数逐层学习

### 1. 必须会用的初始化接口

| 函数 | 参数、返回值与执行重点 | 例子 |
| --- | --- | --- |
| `sd_init()` | 无参数；`sd_error_enum`；配置硬件、上电识别、获取CID/CSD，先设1位总线 | `status = sd_init();` |
| `sd_card_information_get(p)` | 输出结构体指针；返回状态；解析此前保存的CID/CSD | `sd_card_information_get(&info)` |
| `sd_card_select_deselect(rca)` | 卡相对地址；返回状态；发CMD7 | `sd_card_select_deselect(info.card_rca)` |
| `sd_cardstatus_get(p)` | `uint32_t*` 输出卡状态；返回状态；发CMD13 | `sd_cardstatus_get(&state)` |
| `sd_bus_mode_config(mode)` | 总线宽度配置；返回状态；协商卡侧及主机侧宽度 | `sd_bus_mode_config(SDIO_BUSMODE_4BIT)` |
| `sd_transfer_mode_config(mode)` | 合法模式为DMA或轮询；返回状态；设置内部模式变量 | `sd_transfer_mode_config(SD_DMA_MODE)` |
| `sd_detect()` | 无参数；PD3低返回 `SD_OK`，高返回 `SD_ERROR` | `if (SD_OK == sd_detect())` |

表中例子需逐步检查上一步返回值再进行下一步，不能全部调用完只看最后一次结果。SDIO 的 `SD_OK` 是错误枚举末尾成员，**不是0**；SPI头文件的 `SD_OK` 宏却等于0。两版不能混用头文件或用同一套数字判断。

### 2. `sd_block_read()`：DMA完成与传输完成要区分

```c
sd_error_enum sd_block_read(uint8_t *preadbuffer,
                          uint32_t readaddr,
                          uint16_t blocksize);
```

参数依次为目标缓冲区、卡的字节地址、请求块字节数；返回 `SD_OK` 或具体错误。缓冲区必须有效、足够大，并满足底层32位访问与DMA对齐条件。原驱动检查块长为非零、2的幂且不超过2048；高容量卡会先强制块长512，再把地址除以512。

DMA路径步骤：清理传输状态 → 配置块长CMD16 → 配置SDIO数据状态机 → CMD17读取 → 使能SDIO相关中断与DMA → `dma_receive_config()` → 循环等DMA的FTF标志，计数耗尽则失败。

例如在初始化完成、512字节块长条件下：

```c
/* 学习示例；使用u32数组保证基本32位对齐 */
static uint32_t words[128];
sd_error_enum status = sd_block_read((uint8_t *)words, 512, 512);
if (SD_OK == status) {
    uint8_t first = ((uint8_t *)words)[0];
    /* first 对应卡字节地址512；仍需注意下文的完成与错误检查缺口 */
}
```

单块DMA读取代码没有像写路径那样继续等待 `transend` 并返回 `transerror`，所以当前返回值并不覆盖所有SDIO中断错误。FTF表示DMA搬运完成，不能简单代替完整的卡传输状态验证。

### 3. `sd_block_write()`：为什么必须有SDIO中断

参数为源缓冲区、字节地址、块字节数；返回 `sd_error_enum`。源缓冲区在传输期间应保持有效且不被改写。

DMA路径：清理状态 → 必要时转换高容量地址 → CMD16设块长 → CMD13等卡准备接收 → CMD24写块 → 配置数据传输 → 配置DMA并启动 → 等DMA FTF → 等 `transend` 或 `transerror` → 查询卡状态直到不再处于编程或接收状态。

关键等待原代码：

```c
while ((0 == transend) && (SD_OK == transerror)) {
}
```

对应的中断链：

```text
SDIO事件 → SDIO_IRQHandler → sd_interrupts_process
                         ├─ 完成事件：transend = 1
                         └─ 错误事件：transerror = 对应错误
```

若中断未使能或无法执行，且状态一直不变，上面的循环就无法退出。使能DMA并不自动保证SDIO中断已正确配置。即使正常启用了DMA，CPU仍在函数里等待，`main()`不会同时继续执行其他任务；这是“DMA搬运 + 同步等待”的接口形式。

### 4. DMA配置如何理解

`dma_receive_config(uint32_t *dstbuf, uint32_t bufsize)` 和 `dma_transfer_config(uint32_t *srcbuf, uint32_t bufsize)` 返回 `void`；参数是内存首地址与**总字节数**。两者先清标志、禁用并重置通道，再配置后使能DMA1通道3。

共同配置：外设地址为 `SDIO_FIFO_ADDR`，外设地址不递增，内存地址递增，两边宽度32位，`number = bufsize / 4`。读方向为外设到内存，写方向相反。

例如512字节对应128次32位搬运。把 `u8*` 强转为 `uint32_t*` 只是换一种解释地址的类型，不会自动复制数据、扩容或修正对齐。

已有SDIO链接map中的 `s_arrSDBuffer` 地址为 `0x200011B4`，可确认那一次链接的地址满足4字节对齐；但源码声明 `u8[2048]` 本身没有显式写出4字节对齐约束，今后的布局应重新核对或明确声明。

## 九、源码问题、原因与改进方向

以下“事实”来自当前代码阅读；风险说明是根据代码路径作出的分析，未声称已经在硬件复现。本文只记录建议，没有应用修改。

### 1. 两版共有的问题

| 代码事实与定位 | 原因和可能影响 | 改进方向 |
| --- | --- | --- |
| `Read()` 用2048字节数组，却没有检查对齐后总读取量 | 需求长度小于2048也不保证安全；例如512字节块下 `Read(511,1538)` 需5块，共2560字节，越界条件可由算术确认 | 校验向上取整后的总块字节数，或分块处理；普通GUI读取长度最多255，不能因此把底层接口当成已安全 |
| `ReadSDCard()` 用 `addr + len - 1` 校验 | `len=0` 会产生端点下溢，地址与长度相加也可能回绕；例如addr=1、len=0时端点为0，可能通过范围判断 | 明确拒绝零长度；先检查addr，再用减法校验 `len - 1 <= endAddr - addr` |
| `Read()`、`Write()` 忽略底层读写返回值 | 读失败仍显示旧缓冲区；读改写可能把旧数据写回卡 | 每步检查错误，读取失败立即停止写回；将错误逐层返回、显示 |
| `WriteSDCard()` 先打印请求，内部写函数返回void | 无法据此确认写入成功 | 成功后显示结果，并做读回比较 |
| 缓冲区共享、返回内部指针 | 后续操作覆盖旧内容；未来并发访问会互相干扰 | 文档化生命周期；必要时由调用者提供缓冲区并串行化卡操作 |
| 重插路径只初始化卡，没有重算GUI地址范围 | 换成不同容量卡时，界面的 `endAddr` 仍是旧值 | 初始化成功后更新容量、地址范围与状态；失败时保持不可访问 |
| 字节地址和结束地址均为32位，容量最终换算为32位字节量 | 32位无符号字节总量最大为 `2^32-1`；4GiB容量本身不能表示，乘法可能回绕 | 容量使用64位，乘法在运算前提升类型；或让上层以扇区号组织访问 |
| 启动等待、插卡稳定等待与卡读写阻塞主循环 | GUI和触摸处理延迟；标志不能累计所有漏掉的周期 | 用状态机和基于时间戳的超时组织过程，逐步缩短阻塞段 |
| `HW/Timer/Timer.c` 的中断共享标志未声明 `volatile` | 编译器优化下可见性与轮询行为需审查 | 对中断共享对象声明合适的volatile；另处理读改写竞争、标志丢失，volatile不替代这些设计 |

### 2. SDIO版的具体问题

1. **容量溢出（代码事实）。** `SDCard.h` 的 `card_capacity` 是 `uint32_t`；`sd_card_information_get()` 高容量分支计算 `(c_size + 1) * 512 * 1024`，单位为字节。4GiB及更大容量无法完整容纳，部分容量会回绕为0，进而 `capacity - 1` 变为 `0xFFFFFFFF`。这个“看似覆盖全部32位地址”的范围并不证明容量计算正确。应使用64位容量并同步审查所有地址接口。`sd_card_capacity_get()` 是另一个以KB为结果的接口，不能与该结构体字节容量混为一谈。
2. **初始卡状态未主动赋值（代码事实）。** `s_enumSDCardStatus` 为静态变量，初值为0；但SDIO错误枚举中0是 `SD_OUT_OF_RANGE`，不是 `SD_OK`。初始化后到首次周期检测之前，读写可能被当成未插卡。应在初始化成功后明确设置状态，且区分“插入”和“可访问”。
3. **初始化后续步骤忽略错误（代码事实）。** 业务 `InitSDCard()` 仅循环检查 `sd_init()`，未检查信息获取、选卡、状态获取、切换4位与选择DMA的返回值；局部 `cardstate` 未初始化，若获取状态失败而未写出，后续读它有问题。应逐步检查，初始化变量，并让函数返回状态。
4. **DMA单块读错误处理不完整（代码事实）。** `sd_block_read()` DMA分支使能的是 `SDIO_INT_CCRCERR`，而处理器的数据CRC错误分支检查 `SDIO_INT_FLAG_DTCRCERR`；同时只等DMA完成，不继续检查 `transerror` 和 `transend`。应核对正确中断源，统一完成和失败路径。会在何种卡、时序下出现误报成功，需要故障注入或硬件测试。
5. **部分等待缺少软件总超时（代码事实）。** 写路径等待 `transend` 的循环和某些响应等待没有独立的时间上限；依赖硬件标志和中断到来。应增加基于实际时间的退出与清理流程，失败时停止DMA、清状态并恢复可重试条件。
6. **检测输入为浮空（代码事实）。** `gpio_config()` 将PD3设为浮空输入，而SPI版设为上拉。能否稳定检测取决于板上的检测电路；不能只读源码就认定必然抖动。先查外部上拉，再决定软件配置与消抖。

### 3. 软件SPI版的具体问题

1. **高低速切换为空（代码事实）。** `SetSpeedLow()` 与 `SetSpeedHigh()` 无任何语句，实际每位固定两次10μs延时。可把延时参数化；进一步迁移到硬件SPI时，要重新核对引脚复用与时序，不能只替换函数名。
2. **高容量CSD解析不完整（代码事实）。** `SDGetSectorCount()` 高容量分支只取 `csd[8]`、`csd[9]`，用 `u16 csize` 保存加1后的值；与同目录另一版本的22位 `c_size` 解析相比，遗漏 `csd[7]` 对应高位，加1还可能溢出16位。应完整提取容量字段、用足够宽的中间值，并区分扇区数与总字节数。
3. **取容量失败仍计算结束地址（代码事实）。** `SDGetSectorCount()` 失败返回0，但调用处直接执行 `count * 512 - 1`，结果会下溢成最大无符号值。应先检查0与乘法溢出。
4. **多扇区读取未检查CMD18结果（代码事实）。** `SDReadSector()` 多块分支发CMD18后直接 `RecvData()`，覆盖了命令响应。应命令成功后再收数据，失败时保留原错误并结束传输。
5. **多扇区写错误可能被覆盖（代码事实）。** `SDWriteSector()` 数据循环退出后，将停止令牌 `SendBlock(0, 0xFD)` 的返回值重新赋给 `r1`，可能抹掉前面某块的写失败。应保留首个错误，并单独记录停止结果。
6. **扇区数量未校验（代码事实）。** 数量0落入多扇区分支，`do...while(--sectorNum)` 可能回绕，结合卡响应会出现非预期操作。应拒绝0、无效指针、容量越界和不足的缓冲区。
7. **写入接受不等于编程完成（代码事实与风险分析）。** `SendBlock()` 收到接受响应后直接返回，公开写接口末尾也没有明确等待最后一次卡忙结束。应在报告完成前等待就绪、检查状态，并设置总超时；断电持久性和连续操作表现需上板验证。
8. **计数超时可能非常久（代码可推算）。** `WaitReady()` 最多约 `0xFFFFFF` 次字节交换；按每字节显式延时160μs算，仅延时可达约44.7分钟，再加软件开销。这不是实测等待时间，但足以说明“有计数上限”不等于超时设计合理。应改为基于实际时间的超时。
9. **重插失败结果被忽略（代码事实）。** 任务里调用 `InitSDCard()` 却不检查结果，卡座检测为插入也不等于可用。应保留“检测到卡／初始化中／就绪／故障”等明确状态。

## 十、循序渐进的学习阶段与动手实验

建议分八阶段，每阶段约1～2小时；软件SPI阶段可多留时间画时序图。下面的代码改造练习只作为你后续在实验副本中的练习建议，本文没有替你改动源码。

| 阶段 | 阅读和动手内容 | 预期结果与通过标准 |
| --- | --- | --- |
| 1：辨认工程 | 打开两份Keil工程，定位各自SD驱动；画引脚表与参数单位表 | 能解释同一字节地址为何在两版底层调用中传不同数值 |
| 2：主线与界面 | 阅读Main、GUITop、GUILineEdit，画初始化与回调链 | 能说出20ms、40ms、约1s分别来自哪段计数，知道输入是十六进制 |
| 3：纸面块访问 | 不接板，手算 `Read(510,4)`、`Read(515,10)`、`Write(515,0xA5)` | 分别得到2块、1块、读1块再写1块，并正确画出返回指针 |
| 4：只读软件SPI | 用专用卡启动，串口看初始化信息；通过GUI读取已有区域的少量数据 | 相同地址重复读取应一致；若失败先看命令响应与卡检测，不假设卡里全为0 |
| 5：软件SPI读改写 | 备份测试区域所在的整扇区，记录原内容；在确定可破坏的区域改1字节，再读整块比较 | 目标字节改变，其余字节保持备份内容；失败应查读写返回值，不能只看请求日志 |
| 6：理解软件时序 | 调试器单步或逻辑分析仪观察ReadWriteByte；统计一次读512字节耗时 | 看到高位先发、每位一个时钟周期；测得耗时包含命令和等待，不能只按数据延时认定 |
| 7：换SDIO对照 | 重新下载SDIO工程；在sd_block_read/write和SDIO_IRQHandler设断点 | 能说明DMA方向、128次32位搬运、FTF和transend区别；中断断点会扰动时序 |
| 8：边界与改进 | 先纸面审查零长度、跨块、容量溢出、读失败；再在副本中添加状态返回和校验 | 能拒绝无效输入，读失败不写回，失败向GUI传播；逐项测试后再考虑文件系统 |

### 1. 三个必须手算的例子

取块长 `B=512`，先用下面公式复核源码的逐次减一：

```text
offset     = addr % B
blockStart = addr - offset
blockCount = ceil((offset + len) / B)  （len > 0，且中间运算不溢出）
```

| 请求 | 块首 | 偏移 | 整块读取量 | 向上层返回的位置 |
| --- | --- | --- | --- | --- |
| `Read(510,4)` | 0 | 510 | 1024字节 | 缓冲区+510 |
| `Read(515,10)` | 512 | 3 | 512字节 | 缓冲区+3 |
| `Read(511,1538)` | 0 | 511 | 2560字节 | 原实现会超出2048字节数组，应拒绝 |

最后一个仅用于纸面检查或已加防护的副本验证，不要在原实现中直接触发越界。

### 2. 写入实验怎样判定成功

先记录测试块所有字节，修改后读回比较；不能只看一个目标字节，否则无法发现同块其他字节被破坏。需要验证掉电保存时，应在卡完成编程并按改进后的完成状态确认后再断电、重启读取，不能把断电时机不明的失败直接归因于指针。

### 3. 最小改进顺序

先完成容量与范围校验 → 再补缓冲区检查和错误传播 → 修正完成与超时处理 → 更新插拔状态 → 再做性能优化。不要在错误处理尚不清楚时先把延时全部删除；软件时序变化需要测量确认。

## 十一、自测问题与逐题参考答案

### 1. 两个版本最核心的区别是什么？

**参考答案：** SDIO版由外设完成卡接口通信、DMA搬运数据；软件SPI版由CPU翻转GPIO并逐位收发。两者上层都把按字节需求转为整块操作，GUI的业务目标基本一致。

### 2. 目前推荐先学哪个，后续以哪个为基础？

**参考答案：** 结合当前指针基础，先用软件SPI版看清字节、命令与缓冲区，再学SDIO版。后续较多数据的存储访问优先以SDIO版发展，但需先补容量、错误、超时等处理；没有实测不能宣称某版已更稳定。

### 3. 字节地址1024在两版底层读取中分别怎样传？

**参考答案：** 512字节块条件下，SDIO版 `sd_block_read(buf,1024,512)`；SPI版 `SDReadSector(buf,2,1)`。SPI第二参数是扇区号，SDIO接口第二参数是字节地址。

### 4. 卡地址515可以转换成 `u8*` 后直接解引用吗？

**参考答案：** 不可以。515是卡存储偏移，不是MCU可直接解引用的卡数据地址；必须经卡命令把数据读入SRAM，再通过缓冲区指针访问。

### 5. `Read(510,4)` 为什么读取两块？

**参考答案：** 地址510、511在第0块，512、513在第1块。对齐到0后需覆盖514字节，512字节块必须读两次；返回缓冲区+510。

### 6. `Write(515,0xA5)` 为什么不直接写一个字节？

**参考答案：** 业务通过整块接口访问卡，需先读512～1023这一块，在缓冲区偏移3修改一个字节，再写回整块，以保留其他511字节。

### 7. `buff`、`*buff`、`&buff` 有什么区别？

**参考答案：** `buff` 是保存的目标地址；`*buff` 是该地址处的字节；`&buff` 是指针变量自身的地址。三者不能互换。

### 8. 驱动参数是指针，为什么仍然说C是值传递？

**参考答案：** 函数获得的是地址值副本，本地 `buf++` 不改变调用者的指针变量；但通过 `*buf` 访问的是同一块数组，写入会改变其内容。

### 9. `Read()` 返回局部变量 `result` 为什么可以？

**参考答案：** 返回的是 `result` 保存的地址值，它指向静态缓冲区；不是返回局部变量自身的地址。函数返回后数组仍存在，但下次操作会覆盖数据。

### 10. 能否对 `Read()` 返回值调用 `MyFree()`？

**参考答案：** 不能。它指向静态数组中的位置，没有经内存池申请；释放它既不符合分配器约定，也不会帮助保存卡数据。

### 11. `GetGUILineEditRusult(...,&value)` 的返回值就是输入数字吗？

**参考答案：** 不是。返回值是成功或失败状态，成功的数字通过 `*result=value` 这种输出参数写回。输入 `10` 得到十进制16。

### 12. 为什么GUI设备结构体必须在初始化返回后继续存在？

**参考答案：** GUI保存了结构体地址，后续用它调用业务函数和显示函数。静态对象可持续存在，普通自动局部对象离开作用域后不能继续通过旧地址访问。

### 13. 两版的 `SD_OK` 都是0吗？

**参考答案：** 不是。SPI头文件定义0；SDIO头文件中它是枚举末尾成员，0对应 `SD_OUT_OF_RANGE`。应使用各自符号比较并避免混用头文件。

### 14. 使用DMA以后，主循环会同时继续工作吗？

**参考答案：** 当前接口不会。DMA负责搬运，但调用函数仍循环等完成或错误，调用栈没有返回到main。实现非阻塞访问还需状态机或其他调度设计。

### 15. 为什么SDIO中断没执行可能卡在写函数里？

**参考答案：** 写函数等待 `transend` 或 `transerror` 改变，这些变量由SDIO中断处理流程更新。状态不变、又没有总超时，等待可能一直持续。

### 16. DMA搬512字节，为什么配置number为128？

**参考答案：** DMA内存与外设宽度均为32位，一次搬4字节，所以512/4=128。字节数和传输次数的单位不同。

### 17. 两个调速函数被调用了，是否说明软件SPI已经提速？

**参考答案：** 不能。它们都是空函数，位操作仍使用固定延时。应看函数实现和测得时钟，而不是只看名字和注释。

### 18. 当前GUI最多读255字节，底层2048字节缓冲区检查还需要吗？

**参考答案：** 需要。GUI限制只约束当前输入路径，其他调用或后续修改仍可传大长度；还要计入块内偏移和向上取整后的实际读取量。

### 19. 容量4GiB为什么不能放进32位字节容量？

**参考答案：** 4GiB是 `2^32` 字节，32位无符号数最大是 `2^32-1`。虽然最后一个字节地址可表示，总字节数却不能，需用更宽类型或扇区计数。

### 20. 检测到插卡是否等于可读写？

**参考答案：** 不等于。CD只是卡座信号；还要确保初始化、选卡、模式配置等成功。拔插后应重新建立状态并更新容量范围。

### 21. 显示 `Write: ...` 后读回不对，应先检查什么？

**参考答案：** 先确认该行只是请求日志，再查看整块读取是否成功、写入返回值、地址单位、块对齐、初始化和完成状态；不能只因目标字节不对就认定是指针错误。

### 22. 为什么不能仅凭代码说PD3浮空配置一定出错？

**参考答案：** 板上可能存在外部上拉或其他检测电路。代码只能确认输入模式；稳定性要对照原理图并测试。相反，32位容量溢出可直接用类型和算术证明，不需要上板才能判断。

### 23. 这个实验读写的是文件吗？

**参考答案：** 不是，是卡原始块中的字节。文件系统将文件名、目录等映射成块访问，是后续的一层；原始写入可能破坏已有文件系统信息。

### 24. 完成本实验的最低标准是什么？

**参考答案：** 能画出初始化与按钮回调链，解释两版地址单位，手算跨块读取与读改写，正确理解缓冲区指针生命周期，说明DMA与等待的关系，并指出容量、越界、错误和插拔处理的改进点。

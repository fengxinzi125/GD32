# 实验十一：GD32 以太网硬件学习路径与代码导读

这份笔记面向当前的 `11.Ethernet` 工程，延续实验六“先看项目、再讲原理、最后上板验证”的写法。学完后，你应能从地址推导出板上的总线动作，解释 DM9000 怎样收发数据，并把“连不上”定位到总线、物理链路、IP 或 TCP 中的一层。

本文依据 Keil 工程配置、项目源码、已有链接映射和芯片手册整理。引脚按代码和 MCU 复用表标注，板上实际连线、晶振和 SRAM 型号需结合原理图或实物确认。后面的实验现象是预期，本次未重新编译、烧录或上板测量。以下源码路径以 `11.Ethernet` 为基准。

## 一、先知道这个项目在做什么

这是一个 **GD32F303ZE 裸机以太网实验**。开发板上的 DM9000 负责接入有线以太网，GD32 通过 EXMC 搬运以太网帧，lwIP 在 MCU 上处理协议。板子运行 TCP 服务端，电脑作为客户端。电脑发来的短文本显示在板载 LCD 上，板子也可以把触屏录入的内容发给已连接的客户端。

| 知识点 | 项目中的实际用途 | 首先观察什么 |
| --- | --- | --- |
| 复位、Flash、RCU 和 PLL | 启动固件，建立 CPU 与各外设的时钟 | SWD 能否停在 `main()`，时钟寄存器是否符合配置 |
| GPIO 和引脚复用 | 驱动 LED、复位线、背光，或把引脚交给 EXMC、USART | 输出电平及 EXMC 片选脉冲 |
| EXMC、异步 16 位总线和地址映射 | 共用数据线访问 LCD、DM9000 和外部 SRAM | 同一次访问中片选、读写信号和地址线的变化 |
| DM9000、MAC、PHY、网口 | 搬运以太网帧并建立 10/100 Mbps 链路 | 芯片 ID、链路灯、速率和双工日志 |
| EXTI 和 NVIC | 把 DM9000 的 INT 信号接入 Cortex-M4 的中断系统 | PG6 电平、EXTI 挂起位、是否反复进入 ISR |
| 内外部 SRAM | 保存程序变量、任务栈、pbuf 池和 lwIP 堆 | `.map` 中的地址与 `memp_memory`、`ram_heap` |
| TIMER2、TIMER5、SysTick | 产生任务节拍、累计运行时间和实现延时 | LED 翻转间隔、定时器更新事件 |
| USART0 | 输出 LCD、触摸、网卡和 IP 初始化日志 | PA9 上的串口波形和终端文本 |
| 并口 LCD 与软件 I²C | LCD 显示交互界面，GT1151Q 上报触点 | LCD ID、I²C ACK、触点坐标 |
| ARP、IPv4、DHCP、ICMP、TCP | 地址获取、同网段转发验证和双向文本通信 | ARP 解析、ping、TCP 连接及实际数据 |

`FW` 是厂商外设库，`ARM` 含启动文件、CMSIS 和中断入口，`HW` 是板级外设初始化，`App` 是器件驱动和界面，`TPSW` 是 lwIP 及其移植。按 `.uvprojx` 核对实际参与构建的文件，再以 `main()` 的调用链确认运行路径。工程目录也包含未选用的 TCP 客户端、UDP 演示、GUI 模块和 RTE 同名启动文件。以太网帧在 `DM9000.c` 中由 CPU 通过 EXMC 读写，`lwipopts.h` 的 `NO_SYS=1` 对应裸机 Raw API。

### 2. 追一条真实消息

```text
收：网线 → DM9000 PHY/MAC → RX FIFO
   → DM9000ReceivePacket() → pbuf → ethernetif_input() → ethernet_input()
   → lwIP TCP → TCPServerRecvCallback() → 接收环形队列
   → ReadClientData() → GUI 终端 → LCD

发：触点 → GUITask() → sendCallback → WriteTCPServer() 写入发送缓冲区
   → TCPServerPollCallback() → tcp_write() → lwIP → netif 的 linkoutput
   → DM9000SendPacket() → TX SRAM → PHY → 网线
```

TCP 是字节流。屏幕上一行的边界由业务每次读取的长度决定，电脑端一次发送的数据可能被拆成几段显示。板端每次从每个客户端最多取 63 字节，再补字符串结束符。触屏发送时填写的是**已连接客户端的 IP**，电脑连接时填写的是**板子的 IP 和端口**。

## 三、EXMC 与 GPIO：是什么、为什么、怎么做

**是什么**　EXMC 把 MCU 地址空间中的一段地址转换成板上的并行总线操作。数据线负责搬数据，地址线负责选择位置，片选决定哪个器件响应，`NOE` 和 `NWE` 分别提供读、写选通。GPIO 配为复用后由 EXMC 控制这些引脚。普通 GPIO 输出则用于复位和背光，上拉输入用于读取网卡 INT。

**为什么**　LCD、SRAM 和 DM9000 可以共用 16 根数据线，却需要不同的片选和访问时序。EXMC 按访问地址决定片选，并按区域配置产生脉冲。即使配置项写的是 SRAM 类型，也可以用这套异步总线时序访问实现类似主机接口的 LCD 和网卡。

**怎么做**　先开 GPIO 和 EXMC 的时钟，设引脚复用，选 16 位宽、地址与数据分离，配置异步读写时序，再启用区域。对照代码如下。

| 设备 | Bank0 区域、片选 | CPU 侧地址 | 通用数据建立时间配置字段 |
| --- | --- | --- | --- |
| LCD | Region1，PG9 / EXMC_NE1 | 命令 `0x64000000`，数据 `0x64000002` | 读 15，扩展模式独立写 2 |
| DM9000 | Region2，PG10 / EXMC_NE2 | 索引 `0x680000FE`，数据 `0x68000100` | 读写 3 |
| 外部 SRAM | Region3，PG12 / EXMC_NE3 | 数据区从 `0x6C000000` 开始 | 读写 3 |

公共数据线配置在 PD14、PD15、PD0、PD1、PE7～PE15、PD8～PD10，PD4 和 PD5 分别为 `NOE`、`NWE`，PE0 和 PE1 为 SRAM 的字节选通信号 `NBL0/1`。表中时间值是配置字段，实际脉宽需结合 HCLK、EXMC 时序图和寄存器编码。这个项目的设置可作为观察起点，换器件时应按它的数据建立、保持和访问时间重算。 [GD32F30x 用户手册](https://www.gd32mcu.com/data/documents/userManual/GD32F30x_User_Manual_Rev3.4.pdf) · [GD32F303xx 数据手册](https://www.gd32mcu.com/data/documents/datasheet/GD32F303xx%20Datasheet_Rev3.3.pdf)

### 手算 DM9000 两个端口

`StructDM9000Base` 的两个字段都是 `volatile u16`。`reg` 在基地址，`data` 紧接着，偏移 2 字节。16 位非复用总线下，CPU 字节地址的 bit 1 对应外部 A0，因此 CPU 的 bit 8 对应外部 A7。结合 PF13 的复用功能和两个地址，可以推导出代码预期 PF13 / A7 用于选择 DM9000 的 CMD。用原理图或逻辑分析仪确认这条连线。

| 操作 | CPU 地址 | CPU bit 8 / EXMC A7 | DM9000 主机端口 |
| --- | --- | --- | --- |
| 写寄存器编号 | `0x680000FE` | 0 | INDEX |
| 读或写该寄存器 | `0x68000100` | 1 | DATA |

当代码执行 `ReadReg(DM9000_VIDL)` 时，先向索引端口写编号 `0x28`，再从数据端口读值。这里有三种量，分别是 **CPU 地址**、**网卡寄存器编号**和**寄存器值**。按相同方法可以推导 LCD 的两个地址只切换外部 A0。用 `volatile` 表示每次读写都实际访问硬件。调试时用变量保存刚读出的数据，避免在监视窗口持续读取 FIFO 数据口而改变读指针。 [DM9000A 数据手册的主机接口章节](https://www.davicom.com.tw/pddocs/DM9000A-DS-F01-030311.pdf)

## 四、DM9000 和有线以太网：是什么、为什么、怎么做

**是什么**　MAC 处理以太网帧及 MAC 地址，PHY 处理网线上的电气信号、链路速率和双工协商。DM9000 把这两部分与收发缓冲区接在一起，在 MCU 一侧呈现并行主机接口。网口连接器、网络变压器及差分线属于板级电路，具体连接以板卡原理图为准。 [DM9000A 数据手册](https://www.davicom.com.tw/pddocs/DM9000A-DS-F01-030311.pdf)

**为什么**　CPU 需要知道一帧从哪里读、读多少字节、是否正常，以及什么时候可以提交下一帧。芯片 ID 测的是 **MCU 到网卡芯片**，链路灯测的是 **网卡 PHY 到对端 PHY**。两者通过后，再用 ARP、ping 和 TCP 各验证一层。

**怎么做**　从 `InitDM9000()` 开始。PG7 拉低、拉高执行硬件复位，再经 NCR 做软件复位。读 `VIDL/VIDH/PIDL/PIDH` 四个寄存器，按低到高的顺序拼成 `0x90000A46`。接着设定 `DM9000_AUTO`，通过 `EPAR/EPCR/EPDR` 间接访问 PHY 寄存器，看串口输出协商速率和双工状态。首字节为 `02` 的 MAC 是代码生成的本地管理单播地址，末三字节取自 MCU 指定地址的读值，多板测试时可以从串口核对是否重复。

- **接收**　`MRCMDX` 探测是否有帧，`MRCMD` 读出状态和长度，再每次取一个 16 位字搬到 pbuf。驱动用状态位与长度条件判断是否丢帧。pbuf 可能是一条链，`len` 是当前节点的长度，`tot_len` 是从当前节点起这一包的剩余总长度。
- **发送**　`MWCMD` 选择写 TX SRAM，按低字节在前把两字节拼成一个半字，最后一个字节可单独写入。真实发送字节数写入 `TXPLL/TXPLH`，再写 `TCR` 请求发送，并轮询完成位。例如 `11 22 33` 写成 `0x2211` 和 `0x0033`，长度寄存器写 3。
- **中断**　PG6 是上拉输入，选 EXTI6 下降沿，IRQ 入口是共享的 `EXTI5_9_IRQHandler()`。ISR 保存当前 DM9000 索引，读取并回写芯片的中断状态，最后恢复索引。实际收帧走主循环的 `LWIPReadPackHandle()`。上板联调时可分别在两处设置断点，比较 ISR 与收包函数的调用时机。

芯片 ID 正确只说明寄存器访问基本通畅。链路协商失败时 `InitDM9000()` 会打印 `DM9000 Establish Link Failed!`，之后仍返回 0；界面显示初始化成功时也应独立检查物理链路。

## 五、支撑网络实验的硬件：是什么、为什么、怎么做

### 1. 时钟、定时器、SysTick 和中断

**是什么**　RCU 提供时钟选择、分频和外设门控。定时器计数到周期值后产生更新中断，NVIC 决定中断何时进入 CPU。SysTick 是 Cortex-M4 内核的独立定时器。

**为什么**　串口波特率、外部总线时序和软件周期都依赖时钟。系统频率变化时，即使程序还在运行，串口也可能出现乱码，网络任务的定时也可能偏离预期。

**怎么做**　从选中的 `ARM/System/startup_gd32f30x_hd.s` 看 `SystemInit()`，再到 `InitRCU()`。工程目标按 HXTAL 8 MHz、PLL ×15 配置为 120 MHz，AHB 为 120 MHz，APB1 二分频为 60 MHz。在该配置下，APB1 定时器时钟倍频回到 120 MHz。TIMER2/TIMER5 设置 `PSC=119`、`ARR=999`，所以更新周期为 `(119+1) × (999+1) / 120 MHz = 1 ms`。 [GD32F30x 用户手册的 RCU 与 TIMER 章节](https://www.gd32mcu.com/data/documents/userManual/GD32F30x_User_Manual_Rev3.4.pdf)

| 路径 | 标志及时序 |
| --- | --- |
| TIMER2 | 每次更新累计 `GetSysTime()` 的毫秒计数，置 1 ms 标志；每两次置 2 ms 标志 |
| TIMER5 | 累计 1000 次更新置 1 秒标志 |
| SysTick | 以 `SystemCoreClock / 1000` 配置节拍，给 `DelayNms()` 的阻塞等待递减计数 |
| 触摸与界面 | 触摸约 20 × 1 ms；网络和 GUI 任务约 20 × 2 ms，即 40 ms |
| LED | PA8、PE6 每处理 250 次 2 ms 标志翻转一次，理想为每 500 ms 翻转，完整周期约 1 秒 |

上面的主循环周期以标志及时处理为前提。标志是一位状态，主循环阻塞期间多个节拍可能合并；读源码时以计数条件为准。延时用的 `DelayNus()` 是空循环，核对软件 I²C 速率时以实际波形为准。若更换晶振或调整时钟，核对 RCU 寄存器、`SystemCoreClock` 和实测节拍。

### 2. Flash、片内 SRAM、外部 SRAM 和网卡缓冲区

**是什么**　工程的 Flash 区从 `0x08000000` 开始，大小 512 KiB，放代码、字库和图片等常量。内部 SRAM 区从 `0x20000000` 开始，配置 64 KiB，放全局变量、栈等运行数据。外部 SRAM 经 EXMC 访问，DM9000 自己还有通过数据端口读写的收发缓冲区。

**为什么**　lwIP 的堆和包缓冲池会消耗 RAM。把它们放在外部池，可以把更多片内 SRAM 留给栈和应用。数据池、管理表、C 库堆和网卡收发缓冲区的地址与所有者各不相同。

**怎么做**　先沿用实验六的算法理解 `MyMalloc()`。本实验内池数据区是 **10 KiB**，外池数据区是 **928 KiB**。每块 32 字节，一个管理表项占 4 字节。`InitMemory(SRAMEX)` 清的是外池管理表，所以 EXMC 必须先就绪。`LWIPCommMemMalloc()` 从外池给 `memp_memory` 和 `ram_heap` 申请空间；`MEM_SIZE=10*1024` 表示 lwIP 堆的配置量，和大小恰好相同的自定义内池不是同一个区域。工程选中的启动文件预留栈 12.5 KiB 和 C 库堆 1 KiB。

```text
外池数据     0x6C000000 起                     928 KiB
外池管理表   0x6C0E8000 起   928 KiB ÷ 32 × 4  116 KiB
占用末端     0x6C105000（不含）                 1044 KiB 合计
```

已有 `.map` 显示两个外部区是 `UNINIT`，启动时的 C 运行时不清零，由应用初始化管理表。若实板只装 1 MiB SRAM，当前布局会超出 20 KiB。更高地址可能访问失败，也可能在部分地址线未连接时镜像到低地址。上板前先对照芯片型号和地址走线。需要测容量时，用独立的最小测试固件，在确认的测试地址验证不同地址能独立保存不同的值，避免和运行中的分配器共用测试空间。

### 3. USART0、LED、LCD 和触摸

| 硬件 | 是什么、为什么用 | 怎么做 |
| --- | --- | --- |
| USART0 | 异步串行接口，提供与网口无关的日志 | PA9 为 TX、PA10 为 RX，`115200, 8N1`。电平兼容的 USB 转串口与开发板共地，TX 和 RX 交叉。查看 `fputc()`，`printf` 逐字节等待发送数据寄存器可写 |
| LED | 用 GPIO 提供可见的运行状态 | 对照 `InitLED()` 和 `LEDFlicker()`，用示波器量 PA8 或 PE6 电平翻转。亮灭的有效电平按原理图判断 |
| LCD | 通过 16 位并口接收控制器命令和像素 | PB0 控制背光。先看 `InitLCD()` 的 NT35510、ILI9806 探测与初始化，再看写命令、设显示窗口、写 RGB565 像素。程序横屏使用 800 × 480 坐标 |
| GT1151Q | 独立的触摸控制器，提供坐标和触点状态 | PB6 为 SCL、PB7 为 SDA，PB8 是 INT，PB9 是低有效复位。复位时控制 PB8 来设置地址，随后设为浮空输入。主循环扫描触点 |

软件 I²C 通过 GPIO 产生 START、STOP 和时钟。应答阶段 MCU 释放 SDA，由接收方在第九个时钟给出 ACK。逻辑分析仪若按 7 位解码应显示 `0x14`，而线上含读写位的地址字节是写 `0x28`、读 `0x29`。例如读产品 ID，跟踪 `IICCommonReadBytesEx()` 先写 16 位寄存器地址 `0x8140`，结束写事务后发起读事务。扫描函数从 `0x814E` 取触点数，再读取触点坐标。横屏时源码执行 `x' = 800 - y`、`y' = x`，可以用四角触点检查方向和边界。

标准 I²C 通常用开漏和上拉；本项目的软件实现将 SCL 和发送阶段的 SDA 配为推挽，SDA 在应答和读数据阶段切换为输入。用它学习时重点观察 SDA 何时由谁驱动。背光亮、LCD 有字、触摸有 ACK、坐标准确是四个可以独立验证的结果。

## 六、从网线到应用，怎么一步一步验证

`lwipopts.h` 启用了 DHCP，所以先以屏幕或串口显示的 IP 为准。DHCP 超时后使用默认 `192.168.1.31/24`，网关 `192.168.1.1`。同网段直连测试可在独立网段给电脑设置一个空闲地址，如 `192.168.1.10/24`。同子网通信不需要通过默认网关。服务端端口为 **8088**，源码有 5 个客户端槽，每槽收、发缓冲各 256 字节。

| 阶段 | 动手做 | 怎么判断 |
| --- | --- | --- |
| 1. 启动 | 用 Keil 打开 `Project/GD32KeilPrj.uvprojx`，核对目标和探针，接串口，再复位 | 能停在 `main()`，串口可读。LCD 或网卡初始化之后再观察主循环 LED |
| 2. 查总线 | 在 `GetDeiviceID()` 返回处看四字节拼接值；有逻辑分析仪就观察 PG10、PD4、PD5、PF13 | 预期 `0x90000A46`。写索引时 A7 低，读数据时 A7 高，PG10 片选随访问有效 |
| 3. 查物理链路 | 用已知可用的网线接电脑或同一个交换机，对照网卡链路灯和串口协商日志 | 看见链路及速率/双工。如果 ID 正常但无链路，先检查线缆、对端口与 PHY |
| 4. 查地址与 IP | 核对双方地址和掩码，用 `ping <板子IP>`，用 `arp -a` 看板子 IP 对应的 MAC | 同网段时先有 ARP 映射，再看 ICMP 回显。如果只做直连，可等待 DHCP 回退后再测试 |
| 5. 查 TCP | Windows 上用 `Test-NetConnection <板子IP> -Port 8088` 做连接检查，然后用 TCP 客户端持续连接并发一小段 ASCII 文本，如 `hello` | 端口检查仅建立测试连接。使用持续连接后，板端串口应报告连接，屏幕终端应显示收到的内容 |
| 6. 验证反向发送 | 保持电脑连接，触屏输入电脑这一网卡的 IP 和短数据（如 `123`），按 Send | 以电脑客户端收到字节为准。板端的发送记录表示数据进入应用缓冲区，实际发送稍后由 lwIP 驱动 |
| 7. 验证时间与内存 | 测 LED 翻转间隔，看 `memp_memory`、`ram_heap` 地址；如备有抓包工具，在实验网卡上观察 ARP、DHCP、TCP 握手 | 能说出每个现象分别经过哪层，并能把两块 lwIP 缓冲定位到外池地址范围 |

`LWIPPeriodicHandle()` 用毫秒计数推进 TCP（250 ms）、ARP（5 s）和 DHCP（500 ms、60 s）定时器，`LWIPReadPackHandle()` 搬入帧。调试时长时间停在断点会改变真实链路上的协议计时。建议先连续运行采集现象，再在目标函数附近短暂停住核查变量。

### 遇到异常怎么查

| 现象 | 最先核对的证据 |
| --- | --- |
| 无串口或乱码 | 先看 MCU 是否进入 `main()`、PA9 是否有波形、串口参数与时钟是否正确 |
| LCD 白屏或触摸失效 | 分别查看背光、LCD 的 EXMC Region1、触摸产品 ID 和 I²C 应答，尤其确认坐标方向 |
| 网卡 ID 恒为全 0 或全 1 | 回查 PG7 复位、PG10 片选、PD4/PD5 读写选通、A7 选择和数据线连接 |
| 链路亮但无 IP | 看 DHCP 是否有响应，观察是否进入超时回退，确认电脑与板地址处在同一子网 |
| 能 ping 但 TCP 失败 | 检查 `tcp_bind()` 和 `tcp_listen()` 的结果、8088 端口和客户端槽 |
| TCP 接通但屏幕或电脑没数据 | 依次断点看 `TCPServerRecvCallback()`、`ReadClientData()`，或 `WriteTCPServer()`、`TCPServerPollCallback()`、`DM9000SendPacket()` |
| 首次运行正常，负载或重试时卡住 | 看 EXTI 挂起位、发送等待条件、收包分配失败和外部 SRAM 管理表是否异常 |

## 七、读代码时值得核对的实现细节

1. **中断有两层状态。** DM9000 的中断来源在芯片 ISR 寄存器中，MCU 的挂起状态在 EXTI6。当前共享 IRQ 处理函数里未清 EXTI6 挂起位，清除动作只出现在初始化。若中断反复进入，用调试器分别看 PG6 与 EXTI 挂起位，结合手册核对两处清除流程。代码要求低有效 INT，换板时还要核对器件的实际极性。
2. **阻塞等待会推迟主循环。** 复位位等待与发送完成等待都可能一直循环；出错时可以先查程序停在哪个寄存器条件。链路协商自带超时，这三处应分别观察。
3. **初始化重试与内存相互影响。** `LWIPCommInit()` 先申请 lwIP 内存，随后网卡初始化失败返回时没有释放这两块，外层又会重试。若网卡 ID 多次失败后开始出现分配失败，记录初始化返回码和外池使用情况，追出第一个故障点。
4. **接收代码以半字搬运。** 阅读 `DM9000ReceivePacket()` 时，手算奇数帧长、pbuf 链末端和分配失败分支。分配失败分支以 `while(len)` 每次减 2，奇数长度时会越过零。可以在纸上演算 `5 → 3 → 1 → -1`，理解为什么它不能代表“还有字节”。
5. **注释、宏与实际调用各有信息。** EXMC 的地址窗按地址表达式和区域配置核对，任务周期按计数条件核对，外部 SRAM 容量按数据区加管理表核对。已有链接映射可以证明软件布局，网卡/屏幕型号和物理容量要由板卡资料或实测确认。

## 八、学完后应该能回答的问题

1. **读 `0x68000100` 时，板上会发生什么？** Region2 选中网卡，外部 A7 为高，EXMC 发出读选通，DM9000 的 DATA 端口驱动数据总线。读到什么由先前写入的索引决定。
2. **拔掉网线后，为什么仍能读到正确的 ID？** ID 沿 MCU 到 DM9000 的本地并行总线读取。拔线影响 PHY 到对端的链路。可同时看串口 ID 和链路灯验证。
3. **为什么 `20` 次 2 ms 标志是 40 ms？** 计数对象是 2 ms 标志。40 ms 是标志及时消费时的名义调度间隔，实际可通过任务入口翻转测试 GPIO 来测量。
4. **为什么外部数据池写着 928 KiB，板上需要预留更多？** 每 32 字节还需要一个 4 字节表项，表本身又占 116 KiB。
5. **电脑能 ping 通却连不上 8088 时先看什么？** 先检查服务端是否创建监听、端口是否正确、是否有空闲客户端槽，并看 TCP 握手。此时已经获得一条 IP 层连通的证据。
6. **为什么触屏 Send 之后还要等电脑验证？** 界面先把字节写入应用发送缓冲，随后由 Raw API 回调入 TCP 队列，经网卡送出。只有电脑端收到内容，才能确认完整路径成功。

完成一次上板实验后，留下四项记录：读到的 DM9000 ID、协商出的速率与双工、板端 IP 和一次双向通信的串口或界面记录。再尝试脱离代码手画出 EXMC 两次访问、接收帧到 LCD 以及发送回电脑的三条路径。

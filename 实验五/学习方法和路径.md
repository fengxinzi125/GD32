我看了主程序、界面调用和 NAND 驱动。**这是一个基于 GD32F303ZE 的外部 NAND Flash 读写实验项目，使用 Keil 工程，采用裸机循环运行。**

它实现的功能是：在触摸屏上输入地址和数据，点击 READ 或 WRITE，读取 NAND 中的数据或修改一个字节，并把操作信息显示到屏幕和串口。

**建议你先从 `Main.c` 看整体流程，然后重点看 `ReadWriteNandFlash.c`，再往下看 FTL 和 NAND 驱动。**

项目的主要目录可以这样理解：

| 目录              | 作用                             | 当前学习重点   |
|:----------------- | --------------------------------:| -------------- |
| `App/Main`        | 程序入口、初始化、周期任务       | 先看           |
| `App/RWNandFlash` | 把界面操作转换成 Flash 读写      | 重点看         |
| `HW/NandFlash`    | FTL 管理和 NAND 底层驱动         | 核心           |
| `App/EmbGUI`      | 按钮、输入框、数据显示           | 先了解回调关系 |
| `HW/EXMC`         | 外部存储总线配置，包含 LCD、SRAM | 辅助理解       |
| `FW`、`ARM`       | 芯片库、启动文件、中断等基础支持 | 暂时按需查阅   |

**第一步：看程序怎么运行**

打开 [Main.c](D:/GD32/GD32/实验五/05.NANDFlashAccess/App/Main/Main.c:181)，重点看：

- `main()`：先初始化硬件和软件，然后不断执行周期任务。
- `InitHardware()`：初始化时钟、中断、串口、定时器和 EXMC。
- `InitSoftware()`：初始化屏幕、触摸、FTL 和读写界面。
- `Proc2msTask()`：累计 20 次后执行读写界面任务，即正常情况下约每 **40 ms** 执行一次。

这里先掌握“初始化 → 主循环 → 根据定时标志执行任务”，不用立即钻进每个外设初始化函数。

**第二步：看一次读写是怎样发起的，这是最适合入手的部分**

打开 [ReadWriteNandFlash.c](D:/GD32/GD32/实验五/05.NANDFlashAccess/App/RWNandFlash/ReadWriteNandFlash.c:60)，必须看懂三个函数：

| 函数                       | 需要掌握的内容                                       |
| -------------------------- | ---------------------------------------------------- |
| `InitReadWriteNandFlash()` | 设置地址范围，把读写函数注册为界面回调               |
| `ReadProc()`               | 把字节地址换算成扇区号，读取一个扇区，再显示指定字节 |
| `WriteProc()`              | 先读取一个扇区，修改其中一个字节，再写回整个扇区     |

`WriteProc()` 的思路尤其重要：

```c
// 1. 读取地址所在的512字节扇区
FTLReadSectors(...);

// 2. 修改扇区中的一个字节
s_arrWRBuff[addr % FTL_SECTOR_SIZE] = data;

// 3. 写回整个扇区
FTLWriteSectors(...);
```

例如，修改地址 `0x205`：

```text
扇区号     = 0x205 / 512 = 1
扇区内偏移 = 0x205 % 512 = 5
```

所以要读取第 1 号扇区，修改缓冲区下标 5 的字节，再写回。

如果想知道“点击按钮为什么能进入 `WriteProc()`”，再看 [GUITask()](D:/GD32/GD32/实验五/05.NANDFlashAccess/App/EmbGUI/App/GUITop.c:119)。这里通过函数指针 `writeCallback`、`readCallback` 调用对应函数。

**第三步：看 FTL，理解为什么写一个字节需要这么多处理**

FTL 就是 Flash 转换层，负责把上层的逻辑地址转换为实际存储位置，同时处理坏块和数据搬移。

打开 [FTL.c](D:/GD32/GD32/实验五/05.NANDFlashAccess/HW/NandFlash/FTL.c:70)，建议按这个顺序看：

| 顺序 | 函数                                       | 必须理解的问题                          |
| ---- | ------------------------------------------ | --------------------------------------- |
| 1    | `InitFTL()`                                | NAND 初始化后，如何恢复地址映射         |
| 2    | `FTLReadSectors()`                         | 扇区号如何转换成块号、页号、页内偏移    |
| 3    | `FTLLogicNumToPhysicalNum()`               | 如何通过 LUT 表找到实际物理块           |
| 4    | `FTLWriteSectors()`                        | 空白页如何写，已写过的页如何更新        |
| 5    | `CreateLUT()`                              | 如何从 Spare 区恢复逻辑块到物理块的映射 |
| 6    | `FTLFineUnuseBlock()`                      | 如何寻找空闲块                          |
| 7    | `FTLBadBlockMark()`、`FTLCheckBlockFlag()` | 如何标记、识别坏块                      |

**其中 `FTLWriteSectors()` 是整个项目最值得细读的函数。**

它的主要处理是：

```text
目标页为空白 → 直接写入

目标页已经写过
    → 找空闲块
    → 搬移原数据，同时合入新数据
    → 更新逻辑块到物理块的映射
    → 擦除旧块，供以后使用
```

理解这一段，就能明白为什么 NAND 不能像普通内存那样随意覆盖修改。

**第四步：看底层 NAND 驱动**

打开 [NandFlash.c](D:/GD32/GD32/实验五/05.NANDFlashAccess/HW/NandFlash/NandFlash.c:96)，第一轮重点掌握：

| 函数                                  | 作用                                             |
| ------------------------------------- | ------------------------------------------------ |
| `InitNandFlash()`                     | 配置 NAND 使用的 GPIO、EXMC 时序、8 位总线和 ECC |
| `NandReadID()`                        | 最简单的“发命令 → 发地址 → 读数据”示例           |
| `NandReadPage()`                      | 页内读取，以及 ECC 校验处理                      |
| `NandWritePage()`                     | 页内写入，并保存 ECC                             |
| `NandEraseBlock()`                    | 按块擦除                                         |
| `NandReadStatus()`、`NandWaitReady()` | 判断操作是否完成、是否成功                       |
| `NandReadSpare()`、`NandWriteSpare()` | 访问坏块标记、映射信息、ECC 等管理数据           |

注意：**NAND 专用的 EXMC 配置在 `InitNandFlash()` 中。** `HW/EXMC/EXMC.c` 里的 `InitEXMC()` 主要配置本项目的 LCD 和外部 SRAM。

读这些函数之前，先记住 [NandFlash.h](D:/GD32/GD32/实验五/05.NANDFlashAccess/HW/NandFlash/NandFlash.h) 中的几个参数：

- 每页主数据区：**2048 字节**，另有 **64 字节 Spare 区**。
- 每块：**64 页**，主数据容量为 **128 KiB**。
- 共 **1024 块**，原始主数据容量为 **128 MiB**。
- FTL 扇区：**512 字节**，每页包含 **4 个扇区**。
- NAND 按页组织读写，**按块擦除**；编程把位从 1 变成 0，恢复为 1 需要擦除。

实际调用主线如下：

```text
main()
  → Proc2msTask()
  → ReadWriteNandFlashTask()
  → GUITask()
  → ReadProc() / WriteProc()
  → FTLReadSectors() / FTLWriteSectors()
  → NandReadPage() / NandWritePage() / 数据搬移和擦除
```

第一轮可以暂时跳过 JPEG/BMP 解码、字体、控件绘制细节和 ECC 纠错公式。**先以“能解释一次读取、一次首次写入、一次重复修改的完整过程”为目标。**

另外，读代码时要留意两处现有限制：`ReadProc()` 只读取一个扇区，跨扇区读取处理不完整；`InitFTL()` 在映射表建立失败时会自动格式化，并擦除好块中的数据。这些是当前代码的行为，不能当作通用读写接口直接照搬。本次只查看了代码，没有修改文件或运行板上验证。

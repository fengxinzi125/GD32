# NAND 密码锁

已将工程主程序切换为独立密码锁实验。密码为一个字节 `0xF3`，不是字符串。

## 编译与下载

1. 用 Keil 打开 `Project/GD32KeilPrj.uvprojx`，选择 `Target 1`。
2. 编译后下载 `Project/Objects/GD32KeilPrj.hex`，或在 Keil 中下载 AXF。
3. 串口设置为 **115200、8 数据位、无校验、1 停止位**。
4. 启动后等待串口出现 `Ready: KEY1=input F3, KEY2=input 12, KEY3=check`。

## 操作

| 操作 | 预期串口结果 |
| --- | --- |
| KEY1（PA0，高电平有效）→ 松开 → KEY3 | `input: 0xF3`，然后 `success` |
| KEY2（PG13，低电平有效）→ 松开 → KEY3 | `input: 0x12`，然后 `failure` |
| 未输入就按 KEY3（PG14，低电平有效） | `failure` |
| KEY1 → KEY2 → KEY3 | 最后一次输入为 0x12，结果为 `failure` |
| 完成一次匹配后再次按 KEY3 | 输入已清除，结果为 `failure` |
| 长按一个按键 | 只触发一次；稳定松开后才能再次触发 |

扫描每 1 ms 在主循环执行，按下和松开均需连续 20 次稳定采样。多个按键一起稳定按下时忽略，直到全部松开。不在中断里执行 NAND 访问或串口打印。

## NAND 保存方式

代码位于 `App/Main/PasswordLock.c`。

- `PreparePassword()`：在物理块 **1008～1023** 中，先查找已有密码记录。
- 坏块标记读取第 0、1 页的 Spare 第 0 字节；发现标记或读取失败就跳过。
- 第 0 页 Spare 第 0～5 字节存在元数据时跳过，避免占用现有 FTL 映射块。
- 如果没有已有密码，检查候选块全部 64 页的 Main 和 Spare；只向全为 `0xFF` 的块写入。
- 调用 `NandWritePage(block, 0, 0, buffer, 512)` 写入第 0 页前 512 字节，并立即读回校验。
- 缓冲区第 0 字节为 `0xF3`；第 1～7 字节为记录标识和版本，其余填充 `0xFF`。ECC 由原有驱动写入 Spare。
- 再次上电时复用已有记录，不重复编程，也不执行块擦除或全片格式化。
- 每次 KEY3 匹配都通过 `NandReadPage()` 从 NAND 读取、验证记录，再比较输入值。读取失败会输出错误提示和 `failure`。

若出现 `no blank good block`，表示这 16 个块中没有可用的空白好块。程序停止密码锁存储初始化，不擦除已有内容；可以根据实际 NAND 使用情况修改 `LOCK_FIRST_BLOCK` 扩大查找范围。

这是独立的物理块实验。主程序已停用 `InitFTL()`、触摸界面初始化和界面 NAND 读写任务；不要同时恢复 FTL 运行。FTL 没有为该记录预留块，恢复 FTL 后，密码块可能被其重新使用或格式化。

## 文件与验证

- `App/Main/Main.c`：初始化和 1 ms 调度接入。
- `App/Main/PasswordLock.c`、`.h`：按键、密码存储和匹配。
- `Project/GD32KeilPrj.uvprojx`：已加入密码锁源文件。
- `tmp/password-lock/Main.original.c`：修改前的主程序备份，保留之前手敲的按键代码。
- `tmp/password-lock/keil-build.log`：Keil 编译日志。
- `tests/password_lock/`：模拟 GPIO/NAND 的主机行为测试；这些模拟头文件只用于测试，不加入 Keil 工程。
